# 0.5.0-multiplayer.1 — website-launched multiplayer Baseplate

Desktop gameplay remains unverified by Hermes; Gemini/the owner must perform the actual multi-client acceptance checklist. Production headless server startup on the ThinkPad is explicitly authorized and is distinct from client/gameplay testing.

- Add the first-party Baseplate website game page: original thumbnail upper left, title/Created by upper right, description below left, live servers below right.
- Add atomic fill-then-create matchmaking with pending-seat reservations/expiry, live host heartbeat and bounded capacity:12 players/instance, four logical instances sharing one isolated first-party process and a configured UDP relay.
- Register the Linux `luani://` handler. It exchanges a one-use90-second launch code over HTTPS and hands off an instance-bound admission in anonymous memory. Reusable website cookies/JWTs and embedded client decryption keys are not used.
- Authenticate again on the dedicated server before spawning. Fetch canonical account username, avatar appearance and private game inventory; remove display-name editing. Server-side leases and boot epochs fence stale writes/heartbeats.
- Replicate movement/players, shared pickups/targets, equipment and tool effects through certificate-pinned DTLS/ENet with bounded JSON packets. The server simulates movement and validates actions rather than trusting client positions/identity.
- Keep fixed-size Figma controls, camera/focus behavior, explicit offline practice and old immutable releases. Chat remains clearly local-only notes; no PvP, shared moderation/chat, creator scripts or Studio are added.
- Keep game hosting off the Pi. The ThinkPad user service has filesystem isolation, no Docker socket, no new privileges and memory/CPU caps. Existing password-manager/Playit services are preserved.

